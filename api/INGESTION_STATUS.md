# Streaming ingestion status

The worker publishes `GET /internal/stream-status` for the API to proxy. It is an operational observation of trace delivery, independent of `/readyz`; broker or storage failure must not prevent a status response. The endpoint returns a bounded JSON object and no broker error text, payloads, credentials, or span identities.

The sampler uses a separate, read-only Kafka client every two seconds with a two-second deadline. It checks topic metadata and the earliest, committed, then end offsets for **all four** `incidentlens-spans-v2` partitions. `lag_records` is the sum of `end − committed`, in Kafka records, only when all four partition observations are complete and consistent. A missing partition, nonempty partition without an initialized commit, committed offset before the retained log start, or commit beyond the end yields `null`, never a synthetic zero. For a pristine partition with `start=end=0` and no commit, the sampler can still know there are zero broker records; it reports zero lag with `reason_code: "empty_partition_uninitialized"` to make clear that no consumer progress has been observed. Future or backward wall-clock observations yield unknown lag with `clock_skew`.

Fields are `mode: "streaming"`, `state` (`ok`, `backlog`, `unavailable`, `stale`), nullable `lag_records`, `partitions_total`, `partitions_observed`, `sampled_at`, `sample_started_at`, `sample_finished_at`, nullable `last_write_at`, `last_commit_at`, nullable decimal-string nanoseconds `processing_delay_ns`, `pending_age_ns`, `processing_state` (`idle`, `running`, `retrying`, `failed`), `reason_code`, and `scope: "consumer_group_lag_and_local_worker_progress"`. Timestamps are UTC. A sample older than ten seconds becomes `stale` with unknown lag even if its last value was zero. `reason_code` is a fixed code, not a raw dependency message.

Write/commit timestamps and delay/age come from the local worker callback; broker lag is consumer-group offset progress. A positive lag can include records already written but not yet committed. Zero lag means this consumer group reached the observed broker end offsets at that instant; it does not prove every upstream span was produced or that ClickHouse queries are complete. Processing age depends on the worker and sampler wall clocks. The API must impose its own short timeout and response-size cap, cache briefly, and show stale/unavailable explicitly rather than displaying an old green result.
